# Frontend

Интерфейс Farm RPG. В разработке страница открывается отдельно от Spring: запросы на `/auth`, `/gameAuth` и `/api` Vite пересылает на `http://localhost:8080`.

Сборка на Vite 6, потому что сейчас установлен Node.js 20.17. Vite 8 требует Node.js 20.19 или новее.

```bash
cd frontend
npm install
npm run dev
```

Страницы входа и регистрации: http://localhost:5173

После входа в приложение фронтенд проверяет игровую сессию через GET `/gameAuth/status`.
Проверка выполняется при открытии страницы, возврате на вкладку и каждые 30 секунд,
пока вкладка видима. Сервер проверяет сохранённые cookies запросом к инвентарю Farm RPG.
Кнопка `Refresh items DB` доступна администратору только при подтверждённой игровой сессии;
иначе предлагается вход в игру. При сетевой ошибке обновление недоступно.

Игровая сессия привязывается к аккаунту приложения после успешного POST `/gameAuth/login`.
Старым аккаунтам нужно один раз повторно войти в игру, чтобы сохранить эту связь.
Cookies остаются на сервере и не возвращаются браузеру. Перед обновлением БД сервер
повторно проверяет игровую сессию и передаёт её cookies в запрос справочника.

POST `/api/items/refresh`
синхронно обновляет справочник со страницы Everything 2 и возвращает числа `found`, `added`,
`updated`. Недостающие иконки скачиваются в фоне. Повторный запуск дожидается сохранения
текущей иконки, останавливает старую очередь и обновляет справочник заново.

GET `/api/items/refresh/status` возвращает `status` (`LOCKED`/`UNLOCKED`) и `delay` в секундах.
Компонент опрашивает сервер через указанную задержку после ответа; при отсутствующем или
неположительном `delay` новый запрос не планируется. При открытии страницы и возвращении
на вкладку состояние проверяется сразу. В скрытой вкладке опрос приостанавливается.
После сетевой ошибки кнопка блокируется, проверка повторяется через 10 секунд.

Иконки сохраняются в `data/item-icons` относительно рабочей папки бэкенда; путь настраивается
через `app.items.image-directory`. Поле `imgSrc` содержит имя файла относительно этой папки,
а до успешного скачивания — `null`. GET `/api/items/{itemId}/icon` отдаёт иконку авторизованному
пользователю (нужен заголовок Authorization; для отображения во фронтенде можно получить Blob).
Резервная копия должна включать БД и папку иконок. Прогресс очереди хранится в памяти одного
процесса: после перезапуска приложения загрузка продолжится при следующем нажатии кнопки.
